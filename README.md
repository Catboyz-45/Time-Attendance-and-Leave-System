# Time Attendance and Leave System (ระบบลงเวลาทำงานและการลา สำหรับ HR)

เว็บแอปสำหรับเจ้าหน้าที่ฝ่ายบุคคล (HR) ใช้บันทึกเวลาเข้า-ออกงาน และการลาของพนักงาน แทนการจดในกระดาษหรือ Excel พร้อมสรุปรายงานรายเดือนสำหรับส่งฝ่ายเงินเดือน

> ระบบนี้ออกแบบให้ **HR ใช้งานเท่านั้น** (พนักงานไม่ได้ login เข้ามาเอง) และควรเปิดใช้งานในเครือข่ายภายในองค์กร

### การอนุมัติการลาทำงานอย่างไร

การอนุมัติเกิดขึ้น **นอกระบบ** เช่น หัวหน้าเซ็นใบลา หรือตอบอนุมัติทาง LINE หรืออีเมล ส่วน HR ทำหน้าที่ **บันทึกผล** ลงในระบบ:

1. ได้รับใบลา → HR บันทึกในระบบเป็น **รออนุมัติ** (ใช้ติดตามใบลาที่ยังรอหัวหน้าเซ็น)
2. หัวหน้าอนุมัติแล้ว → HR กด **บันทึกอนุมัติ** (หรือ ไม่อนุมัติ) และระบุ **ชื่อผู้อนุมัติ**
3. ระบบเก็บข้อมูลทั้งสองฝั่ง:
   - **ผู้อนุมัติ** คือคนที่อนุมัติจริง เช่น หัวหน้างาน
   - **บันทึกผลโดย** คือบัญชี HR ที่กดบันทึก พร้อมเวลาที่บันทึก

ใบลาที่ HR ได้รับมาพร้อมลายเซ็นอนุมัติแล้ว บันทึกเป็น "อนุมัติ" พร้อมชื่อผู้อนุมัติได้ทันที ไม่ต้องผ่านสถานะรออนุมัติ

## 💻 ติดตั้งและเริ่มใช้งาน

ต้องติดตั้ง [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows/macOS) หรือ Docker Engine (Linux) ก่อน

**1. สร้างไฟล์ตั้งค่า**

```bash
cp .env.example .env
```

แก้ไฟล์ `.env` ให้ `DB_ROOT_PASSWORD`, `DB_PASSWORD` และ `SESSION_SECRET` เป็นค่าสุ่มยาวๆ ค่าสุ่มสร้างได้ด้วยคำสั่งนี้:

```bash
openssl rand -hex 32
```

**2. เปิดระบบ**

```bash
docker compose up -d --build
```

**3. ดูรหัสผ่านชั่วคราวของผู้ดูแลระบบ** (สร้างให้อัตโนมัติตอนเปิดครั้งแรก)

```bash
docker compose logs app
```

**4. เข้าใช้งาน** ที่ http://localhost:3000 แล้ว login ด้วย `admin` และรหัสผ่านชั่วคราว ระบบจะให้ตั้งรหัสผ่านใหม่ทันที

**5. ตั้งค่าเริ่มต้น** (ทำครั้งเดียว)
1. **ตั้งค่า** → ตั้งเวลาเข้างาน วันทำงาน โควตาวันลาตามระเบียบบริษัท และเพิ่มวันหยุดของปี
2. **ตั้งค่า → ผู้ใช้ระบบ** → เพิ่มบัญชีให้ HR แต่ละคน (อย่าใช้บัญชีร่วมกัน เพื่อให้ audit log บอกได้ว่าใครแก้ไข)
3. **พนักงาน** → เพิ่มรายชื่อพนักงาน ถ้าใช้เครื่องสแกนนิ้ว ให้รหัสพนักงานตรงกับรหัสในเครื่อง

### ให้เครื่องอื่นในออฟฟิศเข้าใช้งาน

เปิด `http://<IP ของเครื่องที่รันระบบ>:3000` จากเครื่องอื่นในเครือข่ายเดียวกัน (อาจต้องอนุญาตพอร์ต 3000 ใน firewall)

ฐานข้อมูล (พอร์ต 8840) และ phpMyAdmin เปิดให้เฉพาะเครื่องที่รันระบบเท่านั้น

> ⚠️ **อย่าเปิดระบบออกอินเทอร์เน็ตโดยตรง** ถ้าจำเป็นต้องเข้าจากนอกออฟฟิศ ให้ใช้ VPN หรือวางไว้หลัง reverse proxy ที่มี HTTPS แล้วตั้ง `COOKIE_SECURE=true` และ `TRUST_PROXY=true` ใน `.env`

### คำสั่งที่ใช้บ่อย

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `docker compose up -d --build` | เปิดระบบ / อัปเดตหลังแก้โค้ด |
| `docker compose down` | ปิดระบบ (ข้อมูลยังอยู่) |
| `docker compose logs -f app` | ดู log ของเซิร์ฟเวอร์ |
| `docker compose --profile tools up -d phpmyadmin` | เปิด phpMyAdmin ที่ http://localhost:8841 (login ด้วยบัญชี MySQL) |
| `docker compose down -v` | ⚠️ ปิดระบบและ **ลบข้อมูลทั้งหมด** |

## 📥 นำเข้าข้อมูลจากเครื่องสแกนนิ้ว

ไปที่เมนู **นำเข้าข้อมูล** แล้วเลือกไฟล์ CSV ระบบรองรับ 2 รูปแบบ:

**แบบ 1 แถวต่อวัน**

```csv
รหัสพนักงาน,วันที่,เวลาเข้า,เวลาออก
E001,2025-04-02,08:25,17:35
```

**แบบ 1 แถวต่อการสแกน 1 ครั้ง** (ไฟล์ที่ export จากเครื่องสแกนนิ้วส่วนใหญ่เป็นแบบนี้) ระบบจะใช้เวลาแรกของวันเป็นเวลาเข้า และเวลาสุดท้ายเป็นเวลาออก

```csv
AC-No.,Name,Time
E001,สมศักดิ์,02/04/2568 08:25
E001,สมศักดิ์,02/04/2568 17:35
```

- วันที่ใช้ได้ทั้ง `YYYY-MM-DD` และ `วัน/เดือน/ปี` ทั้งปี ค.ศ. และ พ.ศ.
- ระบบจะแสดงผลตรวจสอบก่อนนำเข้าทุกครั้ง (รายการใหม่ / อัปเดต / ผิดพลาด) แถวที่ผิดจะถูกข้ามไป
- ถ้าวันนั้นมีข้อมูลอยู่แล้ว ระบบจะรวมเวลา (ใช้เวลาเข้าที่เร็วที่สุดและเวลาออกที่ช้าที่สุด)
- ไฟล์ Excel (.xlsx) ให้ "บันทึกเป็น CSV" ก่อน

## 💾 สำรองและกู้คืนข้อมูล

สำรองข้อมูล (ไฟล์จะอยู่ในโฟลเดอร์ `backups/` และไฟล์ที่เก่ากว่า 30 วันจะถูกลบอัตโนมัติ):

```bash
sh scripts/backup.sh
```

ตั้งให้สำรองทุกคืนตอนตี 2 (Linux/macOS: เพิ่มบรรทัดนี้ใน `crontab -e` แล้วแก้ path):

```
0 2 * * * cd /path/to/Time-Attendance-and-Leave-System && sh scripts/backup.sh
```

กู้คืนข้อมูล (ข้อมูลปัจจุบันจะถูกแทนที่ทั้งหมด):

```bash
sh scripts/restore.sh backups/webdb-20260101-020000.sql.gz
```

> ควรคัดลอกไฟล์สำรองไปเก็บไว้นอกเครื่องด้วย เช่น NAS หรือ external drive

## 🔒 ความปลอดภัยและ PDPA

ข้อมูลการลาป่วยเป็นข้อมูลสุขภาพ ซึ่งเป็นข้อมูลอ่อนไหวตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล

**สิ่งที่ระบบทำให้แล้ว**
- ต้อง login ทุกครั้ง รหัสผ่านเก็บแบบ bcrypt และ session หมดอายุเมื่อไม่ได้ใช้งาน (ค่าเริ่มต้น 8 ชั่วโมง)
- ใส่รหัสผ่านผิด 5 ครั้งจะถูกล็อก 15 นาที
- บังคับเปลี่ยนรหัสผ่านชั่วคราว
- บันทึก audit log ทุกการแก้ไขและการ login
- ข้อมูลที่ลบยังเก็บไว้ ตรวจสอบย้อนหลังได้
- ป้องกัน XSS, CSRF (cookie `SameSite=Strict`) และ SQL injection
- ตั้ง security headers ด้วย helmet
- API ไม่ให้เบราว์เซอร์ cache ข้อมูล
- แอปใช้บัญชีฐานข้อมูลแยก ไม่ใช่ root
- ฐานข้อมูลไม่เปิดให้เครื่องอื่นเข้าถึง

**สิ่งที่องค์กรควรทำเพิ่ม**
- จำกัดคนที่มีบัญชีเฉพาะผู้ที่จำเป็น และปิดบัญชีทันทีเมื่อพนักงาน HR ลาออก
- ใช้ HTTPS ถ้าเข้าถึงจากนอกเครื่องที่รันระบบ
- เก็บไฟล์สำรองในที่ปลอดภัย และกำหนดระยะเวลาเก็บข้อมูลตามนโยบายขององค์กร
- แจ้งพนักงานว่ามีการเก็บข้อมูลเวลาทำงานและการลาเพื่อวัตถุประสงค์ใด

### API หลัก

ทุก endpoint (ยกเว้น `/api/auth/login`) ต้อง login ก่อน ส่วนที่มีเครื่องหมาย 🔑 ใช้ได้เฉพาะผู้ดูแลระบบ

| Endpoint | คำอธิบาย |
|---|---|
| `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`, `POST /api/auth/change-password` | เข้าสู่ระบบ / บัญชีของตัวเอง |
| `GET /api/dashboard` | ข้อมูลหน้าภาพรวมวันนี้ |
| `GET/POST /api/employees`, `GET/PUT /api/employees/:id`, `GET /api/employees/departments` | พนักงาน |
| `GET/POST /api/attendance`, `GET/PUT/DELETE /api/attendance/:id` | การลงเวลา (กรองด้วย `employee_id`, `department`, `from`, `to`, `late`, `missing_out`, `q`) |
| `GET/POST /api/leave_requests`, `GET/PUT/DELETE /api/leave_requests/:id`, `PATCH /api/leave_requests/:id/status` | การลาและการบันทึกผลอนุมัติ (`approver_name` จำเป็นเมื่อสถานะเป็น approved/rejected), `GET /api/leave_requests/approvers` = รายชื่อผู้อนุมัติที่เคยใช้ |
| `GET /api/reports/monthly?month=YYYY-MM`, `GET /api/reports/leave-balance?year=YYYY` | รายงาน |
| `POST /api/import/attendance` | นำเข้าการลงเวลา (`dry_run: true` = ตรวจสอบอย่างเดียว) |
| `GET /api/settings`, `PUT /api/settings` 🔑 | การตั้งค่า |
| `GET/POST /api/holidays`, `DELETE /api/holidays/:id` | วันหยุด |
| `GET/POST /api/users` 🔑, `PUT /api/users/:id` 🔑 | ผู้ใช้ระบบ |
| `GET /api/audit` 🔑 | ประวัติการแก้ไข |

รายการที่แบ่งหน้าจะตอบกลับเป็น `{ items, total, page, page_size }` ถ้าข้อมูลไม่ถูกต้องจะตอบ `400` พร้อม `errors`

### อัปเกรดจากเวอร์ชันก่อนหน้า

การเปลี่ยนแปลงฐานข้อมูลเล็กๆ (เช่น เพิ่มคอลัมน์) เซิร์ฟเวอร์จะอัปเดตให้อัตโนมัติตอนเริ่มทำงาน (`server/src/migrate.js`) ไม่ต้องลบข้อมูล

ส่วนเวอร์ชันแรกสุด (ก่อนมีระบบ login) โครงสร้างฐานข้อมูลเปลี่ยนไปมาก (เพิ่มตาราง users, employees ฯลฯ) ถ้าเคยรันเวอร์ชันเก่า ต้องสร้างฐานข้อมูลใหม่ คำสั่งนี้จะลบข้อมูลเดิมทั้งหมด:

```bash
docker compose down -v
```

```bash
docker compose up -d --build
```
